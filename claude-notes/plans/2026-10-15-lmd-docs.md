## How the page frames the feature

Decided 2026-10-16. The page presents lmd as two ideas layered, not one, because the combination is what makes it different from a Lua filter:

1. **Markdown in your Lua.** Inside Lua, a piece of markdown is an expression: `{=: … :=}` is a block value and `{=[ … ]=}` an inline value, written as markdown and handed to you as the `pandoc.Blocks` or `pandoc.Inlines` you would otherwise build by hand out of constructors. Inside such a fragment, `` `{lmd} expr` `` puts a Lua value back into the markdown, so the two languages nest in both directions.
2. **Lua in your markdown.** An `{lmd}` cell is a cell whose language is Lua and whose result replaces the cell, at the cell's own position; `` `{lmd} expr` `` in a paragraph does the same for inlines. A cell is an in-place filter: it acts where it is written, and never needs to name a class to match on.

A Lua filter is Lua *for* your markdown, kept in a separate file and applied to the whole document from outside. lmd is markdown right in your Lua, and Lua right in your markdown. The page says this in roughly those words, once, in its opening paragraph, and does not compare the feature to JSX or MDX (readers of a Quarto guide cannot be assumed to know them).

**Title:** `lmd: Markdown and Lua in the same file` (decided 2026-10-16; "in the same file" rather than "together", because a Pandoc filter is also markdown and Lua, in two files). The front-matter `description` carries the one-sentence explanation, and the opening paragraph carries the two-direction phrasing above. In prose the page writes "lmd" lowercase, expands it once as "Lua and markdown", and uses "lmd cell", "inline lmd cell" and "markdown fragment" consistently.

A fact the page states early because it shapes everything else: all the cells of a document run in **one Lua state, in document order**, after the engines have run and before user filters, shortcodes, cross-references and callouts are processed. So a cell can define a function or a variable that a later cell or inline cell uses, and the markdown a cell returns is treated exactly like markdown the author typed.

## The page, section by section

Each section names the pattern, the example it uses, and what the smoke tests on `main` (q2 0.33.0, 2026-10-15) established about it. Snippets are the planned examples; prose is paraphrased.

### 1. A first cell (`@demo-first-cell`)

The motivating example from the PR, unchanged, because it shows the three syntaxes in four lines:

````qmd
---
stuff: [a, b, c, d]
---

```{lmd}
return meta.stuff:map(function(v) return {=: **`{lmd} v`** :=} end)
```
````

renders four bold paragraphs. The prose walks it in the order of the two ideas above: `{=: … :=}` is markdown as a value, the inner `` `{lmd} v` `` puts the Lua value back into the markdown; `meta.stuff` is the front-matter list and `:map` is `pandoc.List`; and the cell returns a list of blocks which replace the cell where it sits.

### 2. Reaching for metadata (live cells on the page, plus `@demo-metadata`)

The pattern the user expects to be the most common. Two halves.

**Reading a value.** `meta.key`, `meta.a.b`, `meta.list[1]`, `meta.authors[2].name`; and `quarto.metadata.get("a.b")` as the form for a path that may be absent (`meta.missing.inner` is a Lua error, `get` returns `nil`). Numeric path segments index lists. One table of what comes back: a YAML string is `Inlines` (so emphasis in a title survives), numbers and booleans are themselves, lists are `pandoc.List`, maps navigate.

**Computing on it, which is where `{{{< meta >}}}` stops.** The page sets the two side by side once, then shows four computations an author actually wants, live, against its own front matter:

````qmd
---
version: 12.1
team: [ada, grace, linus]
---

The team has `{lmd} tostring(#meta.team)` members:
`{lmd} table.concat(meta.team:map(pandoc.utils.stringify), ", ")`.
Version `{lmd} tostring(meta.version)`, lead `{lmd} pandoc.utils.stringify(meta.team[1]):upper()`.
````

Establishes: counting, joining, string methods, and that `pandoc.utils.stringify` is how you get a plain string out of an `Inlines` value when you want to concatenate or compare. Verified on `main`: all four render ("3 members: ada, grace, linus", "12.1", "ADA").

Two gotchas go here, each one sentence:

- A number from metadata must be wrapped in `tostring()` in an inline cell; a bare `` `{lmd} meta.version` `` is an error (bd-iqd6niat, filed from this plan, proposes accepting numbers).
- `table.concat` wants strings, and metadata strings are `Inlines`; hence the `:map(pandoc.utils.stringify)`.

### 3. Repeating markdown over a list (`@demo-lists`)

The second pattern the user named. Three shapes, in increasing generality, each verified:

**Items of a list.** The item of a `pandoc.BulletList` is a list of blocks, so an inline fragment is wrapped in `pandoc.Plain` for a tight list, and a block fragment gives a loose list (paragraph per item):

````qmd
```{lmd}
return pandoc.BulletList(meta.authors:map(function(a)
  return pandoc.Plain({=[ `{lmd} a.name` (`{lmd} a.role`) ]=})
end))
```
````

Verified: tight list "Ada (lead) / Grace (reviewer)". The page says explicitly *not* to pass the inline fragment bare: `pandoc.BulletList(items:map(function(a) return {=[ … ]=} end))` coerces each inline to its own `Plain`, and the item renders one word per line (observed on `main`). And not to return one `{=: - item :=}` per element: a list of one-item lists renders as separate lists with comment separators between them (observed).

**A section per item.** Accumulate with `pandoc.Blocks` and `:extend`:

````qmd
```{lmd}
local out = pandoc.Blocks({})
for i, t in ipairs(meta.team) do
  out:extend({=:
### `{lmd} t`

Member number `{lmd} tostring(i)`.
:=})
end
return out
```
````

Verified. Headings built this way get ids derived from their final text, unique across the document (`ada`, `grace`, `linus`), which the page notes in one sentence since it is what makes the headings linkable and TOC-visible.

**Concatenation.** `a .. b` on two `Blocks` values, for the two-fragment case where a loop is overkill. Verified.

Ordered lists: the example shows `pandoc.OrderedList(items, pandoc.ListAttributes(1, "Decimal", "Period"))` with the explicit attributes, because the default attributes currently break every pandoc-leg format (bd-3h6iasmz, filed from this plan). Once that is fixed the explicit attributes can go.

### 4. Setup cells and shared state (`@demo-shared-state`)

A cell with no `return` leaves nothing in the document and is the natural place for definitions. Everything it defines is visible to every later cell, block and inline, in document order:

````qmd
```{lmd}
greeting = "Hello"
function badge(text)
  return {=[ [`{lmd} text`]{.badge} ]=}
end
```

## `{lmd} greeting`, world

A `{lmd} badge("new")` feature and a `{lmd} badge("beta")` one.
````

Verified, including the heading (id `hello-world`, from the final text). The prose states the rule once: one Lua state per document, cells run top to bottom, a cell inside a div runs before a top-level cell that follows the div, so an inline cell above a setup cell sees `nil`.

### 5. Fragments as functions (`@demo-fragment-functions`)

The component pattern, from the fixtures: a function that takes a title and a body and returns a fragment, with a block cell nested inside the fragment to splice the body. This is the one place the page needs a four-backtick cell and says why (a fence inside a fence):

`````qmd
````{lmd}
local function card(title, body)
  return {=:
::: {.card}
### `{lmd} title`

```{lmd}
return body
```
:::
:=}
end
return card("Hello", {=: Some *body* text. :=}) .. card("Bye", {=: More. :=})
````
`````

Verified. Also the place to say that a fragment with an inline cell that itself contains a code span needs double-backtick delimiters, ordinary markdown nesting.

### 6. Conditional content (`@demo-conditional`)

Short. A cell that returns `nil` vanishes, so `if` around a `return` is all it takes:

````qmd
```{lmd}
if meta.draft then
  return {=:
::: {.callout-warning}
This is a draft of version `{lmd} tostring(meta.version)`.
:::
:=}
end
```
````

Verified: the callout renders as a callout (the callout transform runs after cells). Also `quarto.doc.is_format("html")` for per-format content, one line. The page notes that whatever a cell returns is processed as if typed: callouts, cross-reference labels, divs with classes all work.

### 7. A filter on a piece of markdown (`@demo-walk`)

The "one-off Lua filter" use the user named, in its smallest form: `Blocks:walk` on a fragment, so an author who knows pandoc filters sees that the same vocabulary applies to a value in hand rather than to the whole document.

````qmd
```{lmd}
local frag = {=: Some *text* to shout. :=}
return frag:walk({ Str = function(s) return pandoc.Str(s.text:upper()) end })
```
````

Verified. One sentence that `pandoc.*` constructors are available for anything markdown does not express conveniently, with a pointer to the Lua filters page for the API. No more than that; this page is not the filter reference.

### 8. Seeing what ran, and when a cell fails (`@demo-echo`)

- `--| echo: true` at the top of a block cell keeps the desugared Lua visible above the result (the fragments show as `pandoc.Blocks(...)` calls, which is a fair way to explain what a fragment *is*). Shown once, as the example project.
- A failing cell is an error located at the line, in the document, with the cell left displayed so the page still renders. The page shows one runtime error's diagnostic as a text block (from the `errors.qmd` snapshot), lists the kinds in a sentence (Lua syntax error, unsupported markdown inside a fragment, Lua runtime error, wrong kind of return value, bad cell options), each linked to its new `Q-26-*` reference page, and links to the error reference index (decided 2026-10-16). The diagnostic shown is the runtime error, re-captured after the codes land so it reads `Error [Q-26-4]: …`.
- Writing *about* lmd: `` `{lmd}` `` alone is a mention; a `{lmd}` cell in a `markdown` fence is displayed, not run (link to the computations page, which already explains the fence rule).

### 9. The rules, collected

A reference block the reader can come back to:

- **Return contracts.** Block cell: a Block, a list of Blocks, or nil. Inline cell: an Inline, a list of Inlines, a string, or nil. Strings in inline position split into words and spaces as pandoc does.
- **The three fragment forms** in one table, including `{= … =}` with its two-line summary (blocks where blocks go, inlines where inlines go; a one-paragraph fragment unwraps in inline position). The unmarked form appears only here (decided 2026-10-16).
- **Order.** After engines (`{python}` and `{r}` cells have already run; an lmd cell cannot see their variables and they cannot see its), before user filters, shortcodes, cross-references, callouts. One Lua state per document.
- **Heading ids** follow the final text.
- **What is available in a cell:** the `pandoc` and `quarto` tables a Lua filter gets, `meta`, `quarto.metadata.get`, `FORMAT`, `require` scoped to the document's directory.

### 10. Current limitations

Plain list, each with the workaround where one exists. All verified on `main`:

- Tables inside a fragment (pipe tables and `.list-table` divs) fail the cell; build with `pandoc.Table` or wait for bd-7gqr148v.
- Footnotes inside a fragment fail the cell.
- Shortcodes inside a fragment fail the cell; use `meta` instead of `{{{< meta >}}}` (and the diagnostic currently points at the wrong place, bd-onsqz7sv).
- Inline cells in attribute values (a fenced div's `data-x="…"`, a link title) are not evaluated (bd-0o82ly9c).
- Numbers need `tostring()` in inline cells (bd-iqd6niat).
- `pandoc.OrderedList` needs explicit `ListAttributes` for non-HTML formats (bd-3h6iasmz).
- Modules: a `require` of a `.lmd` file does not work yet; a `.lua` module next to the document does. Reusable lmd modules are coming (bd-76ogq4ew). One line (decided 2026-10-16).

### 11. Where this leads

Two short paragraphs with links, no examples: listings declared with `type: metadata` publish their items at `meta.listings.<id>` for a cell to render (link: the "Listings as data" section of `guides/projects/listings.qmd`); a cell can hand what it builds to a React component with `quarto.component` (link: "Building the element from Lua" in `guides/authoring/components.qmd`), and `examples/websites/09-interactive-listing` has both together. Those pages own the composition patterns.

## Diagnostics: catalog codes for lmd

lmd's diagnostics have no catalog codes today: the five titles below are plain strings passed to `DiagnosticMessageBuilder`, so no `[Q-…]` prefix is printed and no reference page exists. This strand adds a new subsystem, `lmd`, numbered `Q-26` (the next free number after `components`, `Q-25`), following the components precedent (commit `0d1aac42b`: catalog entries, pages, sidebar section, and `with_code` at each site in one commit).

| code | level | title | emitted at | today's title |
|---|---|---|---|---|
| `Q-26-1` | warning | Lua syntax error in an lmd cell | `lmd_desugar.rs`, `LmdError::LuaParse` | lmd cell could not be desugared |
| `Q-26-2` | warning | Unsupported markdown inside an lmd fragment | `lmd_desugar.rs`, `LmdError::Unsupported` (tables, footnotes, shortcodes, CriticMarkup, custom nodes) | lmd cell could not be desugared |
| `Q-26-3` | warning | Inline fragment holds more than one block | `lmd_desugar.rs`, `LmdError::NotInlines` | lmd cell could not be desugared |
| `Q-26-4` | error | lmd cell failed | `lmd_execute.rs`, `LmdCellError::Lua` (compile or runtime error, with traceback) | same |
| `Q-26-5` | error | lmd cell did not return blocks | `lmd_execute.rs`, `LmdCellError::NotBlocks` | same |
| `Q-26-6` | error | Inline lmd cell did not produce inlines | `lmd_execute.rs`, `LmdCellError::NotInlines` | inline lmd cell did not produce inlines |
| `Q-26-7` | error | Invalid lmd cell options | `lmd_execute.rs`, `block_cell_code_and_echo` | lmd cell options are not valid |

Notes on the table:

- Today's single "could not be desugared" warning is split three ways because the three causes have three different fixes, which is what a reference page is for. The problem text and the "left as written and will not run" hint stay.
- A **markdown parse error inside a fragment** keeps the reader's own code (`Q-2-10` and friends): the diagnostic is the reader's, rerooted into the document, with the lmd hint appended. No new code; the `Q-26-2` page cross-references this case.
- `quarto.warn` / `quarto.error` raised by a cell's own Lua carry no code, as in filters.
- Levels stay as they are: desugar failures are warnings (the cell is left displayed and the render continues), execute failures are errors. Not revisited here.
